## 1. 对齐目的

产品文档讲的是"用户能看见、能用到的产品形态"。
技术文档讲的是"系统怎么实现这些产品形态"。

两者必须对齐：
- 产品里说的每件事，技术都能做；
- 技术能做的每件事，产品都有需求。

如果不齐，就会有"产品承诺了但做不出来"或者"技术做了但用户不知道怎么用"的问题。

## 10. Phase 0 Provider 范围决定（2026-09-14 增补）

### 背景

V0.2 第 4 节 Provider Adapter Layer 把 Harness 自带 Agent 和外部 CLI Agent 混在一起描述，Phase 0 应该验证哪个 Provider 不明确。

### 决定

- **Phase 0 只接 PI Agent** 作为首个外部 Provider，跑通"项目 → 员工 → 任务 → 交接"的最小主闭环
- **Claude Code / Codex / OpenCode 等**按统一接口预留目录和类型签名，**Phase 6 之前不实现实际 Adapter**
- Provider Adapter 设计要兼容多 Provider（统一接口），但 Phase 0 只实现 `providers/pi/`

### 已修改

- V0.2 第 4 节：增加"Phase 0 唯一真实实现"标注
- V0.2 第 34 节 Phase 0：明确"只接 PI Agent"，列出具体验证项

### 为什么这样选

- Phase 0 是验证 Harness 插件能力，不是验证多 Provider 切换
- 一个 Provider 跑通主闭环已经能证明可行性
- 两个 Provider 同时上 Phase 0 工程量太大，风险高
- 后面再加第二个 Provider 时，可以基于第一个的经验做得更快

### 风险

- 如果 PI Agent 接口跟 Claude Code 差异很大，Phase 6 接入时可能要小调整 Adapter 抽象层
- PI Agent 起步轻量，但代码能力不如 Claude Code，"程序员"样板可能体验一般
